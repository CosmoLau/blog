# 2025 年终总结

从今年开始，如果没什么大变故的话，打算坚持每年年底写一个年终总结，记录一下今年的生活、发现的有趣项目、学到的新知识，亦或是谈谈自己的想法之类的，内容可能会比较庞杂混乱，所以主要还是作为记录留档。

## 站点建设

目前呈现本篇内容的站点是一个博客站点，我将其解析到了 `blog.cosmolau.top` 这个三级域名下，并将其存储在 GitHub 仓库中，通过 GitHub Pages 进行部署。

::github{repo="CosmoLau/blog"}

但其实现在 `www.cosmolau.top` 站点也是一个博客站点，这个站点是我一开始部署站点，后面我将其迁移到 `blog.cosmolau.top` 这个三级域名下，并做了些许的个性化更改。

<www.cosmolau.top> 站点的内容是存储在 <https://github.com/CosmoLau/site> 仓库里，他是用 `Hexo` 搭建的博客，使用的 `Vivid` 作为博客主题。因为 `Vivid` 的作者不再维护这个 `Hexo` 的主题，转投到了基于 `Astro` 的 `Fuwari` 项目上，所以我也跟着对博客进行了迁移（就是本篇内容呈现的样子）。

::github{repo="CosmoLau/site"}

当时在考虑迁移博客的时候，我进行了一个简单的规划，我认为 `www.cosmolau.top` 或者说 `cosmolau.top` 这个域名不应该用来展示我的博客内容，而应该作为我个人的作品集展示页面，这样才能更好的 showcase，不过羞于至今为止都没有什么拿得出手的项目，所以到现在也没能对作品集页面进行装修。

基于以上想法，对作品集页面的装修工作将作为我 2026 年的目标之一，我希望这个作品集页面不光作为一个自我介绍的页面，也能见证我在技术上的成长，让我的目标更加清晰。

## 生活与工作

基于各种原因，我从 2023 年 10 月就开始在家啃老，一直到 2025 年 8 月才总算找到了工作，不论如何，也算是重新走上了正轨吧。

在家里呆着的这 2 年，其实整个人也是非常煎熬的，每天没有事情干，程序也不想写，只能颓废地打游戏。对于一个普通人来说，梦想真的是奢望，没有经济也没有坚定的信念，就只是空谈，一场幻想罢了。

作为一个从小喜欢玩游戏的重度玩家，到初入职场进入游戏开发行业，我仍然想要做出一款自己的游戏，但至今一事无成。信念啊，金钱啊，时间啊，都是我的借口，一直都只是在逃避，没有真正迈出这一步。但是今年借助 AI 的辅助，真让我成功开发了两个总算看得过去的 DEMO，我认为这是个好兆头，也许我之前连一个 DEMO 都做不出来的原因，就是缺一个全能型的开发搭子。我让 AI 帮我写测试用的数值，帮我分析策划案，真的能让我事半功倍，也比以往更有兴致，觉得至少我想的玩法有个明确的开发方向了。

2026 年，希望能把现在的工作稳住，然后在 AI 的加持下，完成一款能达到上架水准的完整游戏。

## 年度新物

今年开始，我会记录一些新发现的、不错的、甚至已经替换进我的工作流中的应用、网站、软件、硬件或者其他什么的。

### 笔记✍🏻

在笔记这方面，我因为在第一份工作结束时，忘记备份笔记，所以在这方面非常懊悔。从那时起，我在 GitHub 上建了一个名为 `MyNote` 的仓库来管理我所有的笔记。因为我现在都是用 VSCode 作为编辑器来写 Markdown，所以这一套流程还算是比较方便，甚至在今年折腾的过程中，发现可以在 [vscode.dev](https://vscode.dev/) 上非常丝滑的拉取 GitHub 仓库并修改推送，满足了跨平台笔记编写的需求，唯一的缺点就是在手机上访问 vscode.dev，会显得非常的局促，不过用来应急完全是够用的。

### Git 客户端

我在大学时没怎么使用 Git，当开始工作时，Git 成为了必要工具，而我一开始接触到的就是带有图形化界面的 Git 客户端 [SourceTree](https://www.sourcetreeapp.com/)。

说实话，SourceTree 让我又爱又恨，它几乎是陪伴我至今的 Git 客户端，但其在 Windows 上的性能很差劲。直到我在 V2EX 上看到一篇[讨论 Git 客户端的贴子](https://www.v2ex.com/t/1177732)，评论区有人推荐了国人开发的开源 Git 客户端 [SourceGit](https://github.com/sourcegit-scm/sourcegit)，才让我彻底抛弃陪伴已久的 SourceTree。

::github{repo="sourcegit-scm/sourcegit"}

当然，这篇贴子中提到的几款 Git 客户端产品我也有用过，但我体验下来后的感觉是：

| Git 客户端     | 感受                                       |
| :------------- | :----------------------------------------- |
| ugit           | 腾讯系，内置一大堆我用不到的功能，太臃肿   |
| fork           | 非常好，但是不支持多语言，我有多语言强迫症 |
| GitKraken      | 收费，不考虑                               |
| tortoise git   | 疯狂原始龟                                 |
| github desktop | 也是不支持多语言                           |

所以基于体验后的感受，最后选择了 SourceGit，应该至少会长期使用一段时间，不过在最近的使用中，已经发现一个 BUG，问题倒不是很严重，就是当文件只读时，无法提交，已经在相关 issue 中回复了，希望 BUG 都能今早修复吧。

当然，没有使用 Git 客户端的习惯的话，直接使用 IDE 自带的 Git 也能满足基本需求。

## 技术栈

我之前有想过做一个记录自己技术掌握程度的应用，但是在做成之前，[roadmap.sh](https://roadmap.sh/) 是我觉得很不错的一个替代产品，我目前时不时都会在上面更新一下我的掌握情况。

由于今年重新开始参加工作的原因，我算是强行把一些以前想学习的技术栈落实了下来：

* Vue：业务需求要做 `uniapp`，要用到 Vue2，做 Cocos Creator 的扩展开发会用到 Vue3，以前认为 Vue 用着没什么难点，直到那个奇怪的响应式对象引用搞的我有点头大，这就是一部分人说 Vue 是黑魔法的原因吗？
* React：React 也有想吐槽的地方，返回的 HTML 代码块如果需要处理逻辑判断，会显得非常的乱，这点可能没 Vue 的代码和样式分离来的清晰，但是在 JS/TS 代码编写这块，感觉还是更本源一点，暂时没有遇到 Vue 中类似的一些坑。
* Elysia.js：我现在基本上都是使用 `bun` 作为包管理器，也借此了解到 `Elysia.js` 这个后端框架，之前用过 `express`、`koa` 之类的，我感觉使用起来也都没啥差别吧，既然 Elysia.js 说自己性能强，那我就索性一步到位了。然后不出意外的话，就出意外了，他的静态插件不知道是什么原因，打开静态目录下的文件超过一定数量就会有缺失了，后面还是把这一块的工作交给了 Vite 来完成。
* uniapp：如上面所说，业务需要，然后用了之后硬生生给我干成工伤。如果没有跨平台小程序需求，我觉得我应该永远不会使用 uniapp 来开发程序，强绑 HBuilderX 太让人难受了，我现在都是开发用 VSCode 来做，预览打包才在 HBuilder 上进行，甚至预览也不如浏览器上直接预览，DCloud 别抱着你那 HBuilderX 了，拥抱 VSCode 生态不好吗？现在的 AI 编辑器也都是用 VSCode 改的了。

当然还有我最爱的本职技术栈 Cocos，在我觉得他马上要死的时候，他被 SUD 以 5 亿人民币收购了，近期也是规划了 `PinK AI 编辑器` 和 `Cocos Creator 4.x`，那我还能说什么呢，能不能拳打 LayaBox、Godot，脚踢 Unity、Unreal，Make Cocos Great Again！
